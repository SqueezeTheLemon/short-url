# Spec: 숫자형 단축 URL 서비스

## Problem Statement

긴 URL은 공유하기 불편하다. 사용자는 회원가입이나 로그인 없이 긴 URL을 짧은 주소로 바꾸고 싶고, 그 주소를 받은 사람은 어느 브라우저에서 열든 원래 페이지로 이동하길 원한다. 한 번 공유한 주소가 나중에 다른 곳을 가리키거나 사라지면 신뢰할 수 없으므로, 발급된 주소는 영원히 같은 목적지를 가리켜야 한다.

## Solution

공개 도메인 하나에서 누구나 원본 URL을 입력해 `/123` 같은 숫자로만 된 **단축 주소**를 받고 복사할 수 있다. 단축 주소에 접속하면 서버의 HTTP 리디렉션으로 **원본 URL**에 도착한다. **링크**(번호와 원본 URL의 쌍)는 생성 후 수정·삭제·만료·재사용되지 않으며, 서버를 재시작하거나 재배포해도 유지된다. 같은 원본 URL을 다시 입력하면 항상 새 **번호**를 발급한다.

## User Stories

1. As an 익명 방문자, I want 로그인 없이 URL 입력 화면을 바로 쓰고, so that 계정을 만들지 않고도 단축 주소를 만들 수 있다
2. As an 익명 방문자, I want 원본 URL을 입력하고 생성 버튼을 누르면 단축 주소를 보고, so that 바로 공유할 수 있다
3. As an 익명 방문자, I want 복사 버튼 한 번으로 단축 주소를 클립보드에 담고, so that 손으로 드래그해 복사하지 않아도 된다
4. As an 익명 방문자, I want 복사 성공 피드백("복사됨!")을 보고, so that 복사가 됐는지 확신할 수 있다
5. As an 익명 방문자, I want 생성 요청 중에는 버튼이 비활성화되어 있고, so that 실수로 여러 번 생성하지 않는다
6. As an 익명 방문자, I want 잘못된 URL을 넣으면 이해할 수 있는 에러 메시지를 보고, so that 무엇을 고쳐야 하는지 안다
7. As an 익명 방문자, I want http/https가 아닌 주소(예: `javascript:`, `ftp://`)가 거부되고, so that 위험하거나 동작하지 않는 링크가 만들어지지 않는다
8. As an 익명 방문자, I want host가 없는 URL이 거부되고, so that 깨진 링크가 만들어지지 않는다
9. As an 익명 방문자, I want 2048자를 넘는 URL이 거부되고, so that 비정상적인 입력으로 서비스가 오용되지 않는다
10. As an 익명 방문자, I want 이 서비스 자신의 단축 주소를 다시 단축하려 하면 거부되고, so that 리디렉션 루프가 생기지 않는다
11. As an 익명 방문자, I want 시크릿 창이나 처음 쓰는 브라우저에서도 생성과 이동이 되고, so that 쿠키나 저장 상태에 의존하지 않는다
12. As an 익명 방문자, I want 같은 원본 URL을 다시 넣어도 새 번호를 받고, so that 규칙이 단순하고 예측 가능하다
13. As a 단축 주소를 받은 사람, I want 단축 주소를 열면 원본 URL로 즉시 이동하고, so that 추가 클릭 없이 목적지에 도착한다
14. As a 단축 주소를 받은 사람, I want 원본 URL의 경로·쿼리 문자열·프래그먼트가 그대로 유지되고, so that 정확히 공유된 위치에 도착한다
15. As a 단축 주소를 받은 사람, I want 다른 브라우저·다른 기기에서도 같은 목적지로 이동하고, so that 주소를 어디서든 쓸 수 있다
16. As a 단축 주소를 받은 사람, I want 존재하지 않는 번호를 열면 알아볼 수 있는 404 안내 페이지를 보고, so that 주소가 잘못됐음을 안다
17. As a 단축 주소를 받은 사람, I want `/0123`, `/0`, 범위를 넘는 큰 수 같은 비정상 번호도 404 안내를 보고, so that 한 번호가 하나의 표기만 갖는다
18. As a 단축 주소를 받은 사람, I want 숫자가 아닌 경로(예: `/about`)에서는 화면의 "페이지 없음" 안내를 보고, so that 길을 잃지 않는다
19. As a 링크 생성자, I want 한 번 발급된 번호가 다른 원본 URL로 바뀌지 않고, so that 공유한 주소를 믿을 수 있다
20. As a 링크 생성자, I want 누구도 링크를 수정·삭제할 수 없고 서버가 그런 요청을 거부하고, so that 화면을 우회한 요청으로도 링크가 바뀌지 않는다
21. As a 링크 생성자, I want 링크가 자동으로 만료되지 않고, so that 언제 열어도 동작한다
22. As a 링크 생성자, I want 발급된 번호가 다른 주소에 재사용되지 않고, so that 예전 주소가 엉뚱한 곳으로 가지 않는다
23. As a 링크 생성자, I want 서버 재시작·재배포 후에도 기존 단축 주소가 같은 원본 URL로 이동하고, so that 운영 작업이 링크를 깨뜨리지 않는다
24. As 여러 명의 동시 사용자, I want 동시에 서로 다른 URL을 생성해도 번호가 겹치지 않고, so that 남의 링크를 덮어쓰지 않는다
25. As a 운영자, I want 공개 주소가 HTTPS로만 제공되고, so that 복사 기능과 보안이 정상 동작한다
26. As a 운영자, I want DB 비밀번호와 서비스 토큰이 브라우저 코드나 저장소에 들어가지 않고, so that 비밀 정보가 유출되지 않는다
27. As a 운영자, I want 배포 플랫폼이 서버와 DB 연결 상태를 확인할 헬스체크를 갖고, so that 깨진 버전이 트래픽을 받지 않는다
28. As a 운영자, I want push만으로 백엔드가 재배포되고, so that 배포 절차를 매번 기억할 필요가 없다
29. As a 채점자, I want README에서 같은 원본 URL 처리 규칙과 알려진 한계를 확인하고, so that 설계 의도를 이해할 수 있다
30. As a 채점자, I want 공개 주소에서 생성·복사·이동·404·변경 거부·동시 생성 시나리오를 재현하고, so that 요구사항 충족을 검증할 수 있다

## Implementation Decisions

**구조 (ADR-0001)**
- Cargo workspace에 세 crate: Dioxus web 프론트엔드, Axum 백엔드, 둘이 공유하는 API 타입 crate. 별도로 Cloudflare Worker(JS)와 wrangler 설정.
- 공개 접점은 Cloudflare Worker 하나. Worker는 정적 자산(Dioxus web 빌드 산출물)을 서빙하고, `/api/*`와 `^/[0-9]+$` 경로는 Railway 백엔드로 프록시한다. 프록시 경로가 SPA fallback보다 먼저 처리되어야 하며, 백엔드의 3xx는 따라가지 않고 그대로 브라우저에 전달한다. 백엔드 주소는 Worker 환경변수로 둔다.
- 프론트엔드는 API를 상대경로로만 호출한다. CORS 설정 없음.

**번호와 저장 (ADR-0002, ADR-0003, ADR-0005)**
- Postgres 테이블 하나: 번호(BIGINT, `GENERATED ALWAYS AS IDENTITY` 기본키, 1부터), 원본 URL(텍스트), 생성 시각. 원본 URL에는 UNIQUE를 두지 않는다.
- 번호 발급은 DB 시퀀스에만 맡긴다. 애플리케이션에서 번호를 계산하지 않는다. 시퀀스 특성상 번호에 빈 구간이 생길 수 있으며 재사용은 없다.
- DB 트리거로 해당 테이블의 `UPDATE`/`DELETE`를 거부한다.
- 마이그레이션은 서버 시작 시 자동 실행한다.
- sqlx를 쓰되 컴파일 타임 매크로 대신 런타임 쿼리 함수를 쓴다.
- 원본 URL은 `url` crate로 파싱·정규화한 문자열로 저장한다.

**API 계약**
- `POST /api/links`, 본문 `{ "url": string }` → 성공 `201 { "number": i64 }`, 검증 실패 `400 { "error": string }` (사람이 읽을 수 있는 한국어 메시지).
- `GET /{번호}` → 존재하면 `302`, `Location: <저장된 원본 URL>`. 존재하지 않거나 번호 형식이 아니면(선행 0, 0, i64 범위 초과) `404` + HTML 안내 페이지.
- `GET /health` → DB 연결 확인 후 `200`, 실패 시 `503`.
- 링크 리소스에 대한 수정·삭제 라우트는 존재하지 않으며, 해당 메서드는 `405`로 응답한다.
- 단축 주소는 프론트엔드가 현재 origin과 번호로 조립한다.

**입력 검증 (서버)**
- 앞뒤 공백 제거 후 파싱. scheme은 http/https만, host 필수, 최대 2048자.
- 원본 URL의 origin이 공개 도메인(`PUBLIC_ORIGIN` 환경변수)과 같으면 거부한다.

**설정과 비밀값**
- 백엔드: `DATABASE_URL`, `PORT`(Railway 주입, `0.0.0.0` 바인딩), `PUBLIC_ORIGIN`. 모두 환경변수이며 저장소에는 예시 파일만 둔다.
- Worker: 백엔드 origin 환경변수. 브라우저 번들에는 어떤 비밀값도 포함하지 않는다.

**배포 (ADR-0004)**
- 백엔드: Railway가 GitHub 저장소의 multi-stage Dockerfile로 push마다 빌드·배포. Railway Postgres 사용. 헬스체크 경로 `/health`.
- 프론트엔드: 로컬에서 `dx`로 빌드한 산출물과 Worker를 `wrangler deploy`로 Cloudflare Workers(Static Assets)에 배포.

**화면**
- 한 페이지: 원본 URL 입력, 생성 버튼(요청 중 비활성화), 결과 단축 주소, 복사 버튼과 "복사됨!" 피드백, 서버 에러 메시지 표시.
- 숫자가 아닌 미지의 경로는 Dioxus 라우터의 "페이지 없음" 화면.

**로컬 개발**
- Postgres는 Docker 컨테이너로, Railway와 같은 메이저 버전.

## Testing Decisions

- 좋은 테스트는 외부에서 관찰 가능한 동작(HTTP 상태, 헤더, 본문, DB가 거부하는지)만 확인한다. URL 검증·번호 파싱 같은 내부 함수는 따로 단위 테스트하지 않고 API seam을 통해 검증해, 내부를 바꿔도 테스트가 깨지지 않게 한다.
- **Seam ① 백엔드 HTTP API (주력)**: 테스트가 Axum 앱을 띄우고 Docker의 실제 Postgres에 연결해 HTTP로 검증한다. 대상: 생성 201, 검증 실패 400(비 http/https, host 없음, 2048자 초과, 자기 도메인), 리디렉션 302와 경로·쿼리·프래그먼트 보존, 404 HTML(없는 번호, 선행 0, 0, 범위 초과), 수정·삭제 메서드 405, 서로 다른 URL 50개 동시 생성 시 번호 유일성과 각 번호→자기 URL 대응, 같은 DB로 앱을 새로 띄운 뒤 기존 링크 유지, 같은 URL 재입력 시 새 번호.
- **Seam ② DB 불변성**: 앱을 거치지 않고 SQL로 `UPDATE`/`DELETE`를 시도해 트리거가 거부하는지 확인한다.
- **Seam ③ 배포 스모크 스크립트**: 공개 Cloudflare 주소에 대해 생성 → 302 리디렉션 → 404 → 동시 생성을 확인하는 셸 스크립트. Worker 프록시와 3xx 전달은 이 seam에서만 검증된다.
- 프론트엔드는 자동 테스트 없이 PDF의 "확인할 시나리오"를 수동으로 점검한다.
- 기존 테스트 prior art 없음(신규 저장소).

## Further Notes

- 리디렉션은 302를 쓴다. 링크는 불변이라 301도 의미상 맞지만, 브라우저 영구 캐시로 개발·검증이 어려워지는 것을 피한다.
- README에 포함할 것: 같은 원본 URL은 항상 새 번호를 발급한다는 규칙, 번호에 빈 구간이 생길 수 있다는 점, 원본 URL 정규화 저장, 알려진 한계(남용 방지 없음), 로컬 실행·배포 방법, 환경변수 목록.
- 용어는 `GLOSSARY.md`(원본 URL, 번호, 링크, 단축 주소)를 따른다.
